The HTTPS key (0.14.5)

The server makes its own HTTPS key on its first start: <site>/etc/tls/server.p12, a self-signed
certificate (EC P-256, 5 years) for this machine's names and addresses. webserver.tls.san in
etc/server.root.settings adds more names or addresses (before the key is made: delete the file to
make a new one). The start-up line "HTTPS:" shows its SHA-256 fingerprint; compare it with what the
browser shows when it asks whether to trust the certificate.

Your own certificate instead (e.g. from your organisation's CA), as a PKCS12 file:

  openssl pkcs12 -export -in server.crt -inkey server.key -certfile ca.crt -name server -out server.p12

Put it in the site's etc/tls (or anywhere) and set in etc/server.root.settings:

  webserver.keystore.path=etc/tls/server.p12      (relative to the site folder, or absolute)
  webserver.keystore.pwd=<its password>

A key made by hand with Java's keytool, instead of the automatic one:

  keytool -genkeypair -keyalg EC -groupname secp256r1 -alias server -storetype PKCS12 -keystore etc/tls/server.p12 -storepass <password> -validity 1825 -dname "CN=junction.example.org" -ext "SAN=dns:junction.example.org,dns:localhost,ip:127.0.0.1"

A JKS key store from before 0.14.5 still works: name it in webserver.keystore.path.
