# SimWeaver Rift — REST API

SimWeaver Rift is an HLA/DIS datasource gateway. It joins simulation federations as a
passive datasource, decodes everything it receives against the FOM, and offers the result
over HTTPS:

- a **REST API** to manage datasources and to read their objects, classes and interactions
- a **live event stream** (Server-Sent Events) with changes as they happen

The SimWeaver Rift Web UI is built only on this API, so anything the Web UI shows, another
tool can get the same way.

API state: SimWeaver Rift 0.14.1, November 2026.

## 1. Basics

### Base URL and transport

```
https://<server>:<port>/api
```

- **HTTPS only.** Servers often use a self-signed certificate. Clients must then trust it,
  or (for testing only) skip verification, e.g. `curl -k`.
- **Same origin as the Web UI.** No CORS headers are sent, so browser pages on other origins
  cannot call the API directly.
- **Authentication (0.11.0).** Off by default: then anyone who can reach the port can start and
  remove datasources, so limit network access to the server. With `api.auth.enabled=true` every
  call under `/api` (also `/api/events` and `/api/maps`) needs `Authorization: Bearer <token>`
  (or the Web UI's session cookie): see [14](#14-authentication-0110).

### Requests and replies

- Request and reply bodies are JSON in UTF-8. Replies have
  `Content-Type: application/json; charset=UTF-8`.
- `HEAD` is accepted wherever `GET` is, except on `/api/events`.
- A trailing slash on a path is ignored. Path segments are percent-decoded, and their case
  is kept.
- List parameters are **comma separated**: `class=A,B`. When a parameter is repeated
  (`class=A&class=B`), the values are joined the same way.

### Values

| Kind | Format |
|---|---|
| Timestamps | ISO 8601 in UTC with milliseconds: `"2026-10-21T11:43:12.345Z"`. When the milliseconds are zero they are left out: `"2026-10-21T11:43:12Z"` |
| Integers beyond ±(2^53 − 1) | Sent as **strings**, e.g. 64-bit counters and unsigned 64-bit values. JavaScript would otherwise round them |
| `NaN`, `Infinity`, `-Infinity` | Sent as the strings `"NaN"`, `"Infinity"`, `"-Infinity"` (they are not valid JSON numbers) |
| Absent vs. `null` | Optional fields may be absent. Treat an absent field and `null` the same, unless stated otherwise |

### Identifiers

| Id | Example | Notes |
|---|---|---|
| Configuration id | `227688254` | Integer (may be negative). Stable while the configuration file is unchanged |
| Datasource id (`dsid`) | `"bca5e158-e9b8-46b1-939d-e941c54755d1"` | UUID, new for every datasource that is created |
| Instance id (`instanceid`) | `"o1042"` | Short and URL-safe, generated by Rift, unique within one datasource and never reused while it runs. It is **not** the HLA object instance name; that is `instancename` |
| Interaction id (`interactionid`) | `"i48230"` | `"i"` + the `seq` of the interaction |
| Class name (`classnameq`) | `"HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.Aircraft"` | Fully qualified, dot separated. `classname` is the last part (`"Aircraft"`) |

### Sequence numbers

Every datasource has one counter, **`seq`**, that increases with every change: an object
discovered, updated or removed, or an interaction received.

- Every reply under `/api/datasources/{dsid}/…` carries the `seq` at the time of the read.
- An object's **`rev`** is the `seq` of its last change. On the event stream it travels as
  `@rev` (section 8).
- With `rev` a client can tell which of two copies of an object is newer, for example a
  REST reply and a live patch that cross each other.

## 3. Server

### 3.1 `GET /api/serverinfo`

Version and resource use of the server process. Cheap to call; the Web UI polls it every
5 seconds.

```json
{
  "serverinfo": {
    "name": "SimWeaver Rift",
    "version": "1.0.0",
    "started": "2026-10-21T06:00:00.112Z",
    "now": "2026-10-21T07:30:00.481Z",
    "uptimeseconds": 5400,
    "pid": 12345,
    "java": "11.0.21",
    "os": "Windows 10 10.0 amd64",
    "cpu": { "process": 3.4, "system": 17.2, "cores": 8 },
    "memory": {
      "heapused": 412316860, "heapcommitted": 805306368, "heapmax": 4294967296,
      "nonheapused": 98566144, "processcommitted": 1610612736,
      "physicaltotal": 34359738368, "physicalfree": 12884901888
    },
    "threads": 57,
    "datasources": 2,
    "syslog": {
      "enabled": true, "target": "logs.example.org:6514", "protocol": "tls", "format": "rfc5424",
      "level": "INFO", "connected": true, "connectedsince": "2026-10-21T06:00:01.020Z",
      "sent": 1520, "queued": 0, "dropped": 0
    },
    "j2j": { "state": "running" }
  }
}
```

| Field | Meaning |
|---|---|
| `version` | Server version text, `"unknown"` if not available |
| `cpu.process` | CPU use of the server process in **percent of the whole machine** (0–100, all cores together, as the Windows Task Manager shows it). Measured since the previous call, over at least 1 second; the first call gives the average since start |
| `cpu.system` | CPU use of the whole machine, in percent |
| `cpu.cores` | Processors available to the server |
| `memory.*` | Bytes. `heap*` = Java heap; `processcommitted` = memory committed to the process; `physical*` = the machine's RAM |
| `threads` | Live threads in the server process |
| `datasources` | Running datasources |
| `syslog` | 0.9.22. `{"enabled": false}` without syslog. Otherwise its settings (`target`, `protocol`, `format`, `level`; install guide 2.7) and state: `connected` (UDP: once the address is known), `connectedsince`, messages `sent`, `queued` (waiting for the syslog server) and `dropped` (the queue was full), and after a problem `lasterror` / `lasterrortime` |
| `j2j` | 0.10.0. `{"state": "off"}`, `"running"` or `"error"`: the J2J network (install guide 2.8, [j2j-rest-api.md](j2j-rest-api.md)) |

Any `cpu` or `memory` value is `null` when the Java runtime cannot tell.

### 3.2 `GET /api/maps`

The background maps of the map view, and whether the map is on (server setting `map.enabled`).

```json
{ "enabled": true,
  "maps": [ { "id": "HYP_HR_SR_W_DR", "name": "Natural Earth cross blended hypso (high res)",
              "file": "HYP_HR_SR_W_DR.tif", "width": 21600, "height": 10800,
              "bounds": { "west": -180, "south": -90, "east": 180, "north": 90 },
              "minzoom": 0, "maxzoom": 6, "tilesize": 256, "format": "jpg",
              "version": "1a2b3c4d5e", "tiles": "maps/HYP_HR_SR_W_DR/tiles/{z}/{x}/{y}.jpg?v=1a2b3c4d5e",
              "reader": "uncompressed TIFF, 3 x 8 bit RGB, strips of 1 row",
              "georeference": "whole globe (no georeferencing found)", "attribution": "Natural Earth" } ],
  "default": "HYP_HR_SR_W_DR",
  "overlays": [ { "id": "towns", "name": "Towns", "file": "towns.shp", "visible": true, "color": "#4a2c2a",
                  "minzoom": 0, "maxzoom": 18, "state": "ready", "kind": "point", "features": 1956,
                  "crs": "SWEREF99_TM (Transverse Mercator, GRS 1980)",
                  "bounds": { "west": 11.12, "south": 55.34, "east": 24.15, "north": 69.05 },
                  "version": "5f3a9c", "tiles": "maps/overlays/towns/tiles/{z}/{x}/{y}.png?v=5f3a9c",
                  "labels": "maps/overlays/towns/labels", "labelcount": 1956, "labelminzoom": 6, "labelcolor": "#1b2631" } ],
  "problems": [],
  "stats": { "tilesmade": 85, "tilesserved": 240, "memorytiles": 85, "memorybytes": 1834000, "overlaytilesmade": 40 } }
```

`version` changes with the map file and the tile settings, and is part of `tiles` (`?v=`), so
browsers do not show cached tiles of a replaced file. `enabled: false` (and no maps) when the map
is turned off. `maps` is in the order of the map chooser:
`map.file`, `map.files`, then the map folder. `default` is the map to show when the user has not
picked one (`map.file`, else `map.default`, else the first); `file` is the file name only. `problems`
lists maps that could not be read, a missing `map.file`, and georeferencing warnings, and
overlays that could not be read.

`overlays` are the shapefile overlays (installation guide 2.5), in the order of the overlay menu.
`file` is the `.shp` file name, or for a layer in a zip package the package and the entry
(`ne_10m_airports.zip!ne_10m_airports.shp`).
`state` is `loading` while the server reads a file (at start-up, in the background), then
`ready` or `failed`. Only a ready overlay has `kind` (`point`, `line`, `polygon` or `mixed`),
`features`, `crs`, `bounds`, `tiles` and, when it has labels, `labels`, `labelcount`,
`labelminzoom` and `labelcolor`. `fill` is listed when polygons are filled, and `warnings`
when the server had remarks (no `.prj`, a datum without shift, a missing label field).

### 3.3 `GET /api/maps/{mapid}/tiles/{z}/{x}/{y}.jpg`

A 256 × 256 Web Mercator tile (EPSG:3857, the `z/x/y` scheme of OpenStreetMap), `image/jpeg`,
cacheable for a day. Zoom 0 to the map's `maxzoom`; clients scale the deepest tiles for closer
zooms. Tiles are made from the raster when first asked for and kept in memory and in
`maps/cache`.

`404 MAP_UNKNOWN`, `404 TILE_UNKNOWN` (outside the zoom range or grid), `404 MAP_DISABLED`,
`500 TILE_FAILED`.

### 3.4 `GET /api/maps/overlays/{id}/tiles/{z}/{x}/{y}.png`

A 256 × 256 transparent PNG with the overlay's shapes, same tile scheme as 3.3, zoom 0 to 18;
cacheable for a day (the `?v=` of `tiles` changes with the files and the style). Where the
overlay has nothing, the answer is a 1 × 1 transparent PNG.

`404 OVERLAY_UNKNOWN`, `404 TILE_UNKNOWN`, `503 OVERLAY_NOT_READY` (the file could not be read,
or it is still being read after a minute).

### 3.5 `GET /api/maps/overlays/{id}/labels`

`?bbox=west,south,east,north&zoom=<0-18>`: the labels in the box at that zoom, in the order they
win where they overlap (by `labelrank`, then file order), at most 600.

```json
{ "overlay": "towns", "zoom": 7, "truncated": false,
  "labels": [ { "t": "Stockholm", "lat": 59.3293, "lon": 18.0686, "k": "point" },
              { "t": "Göteborg", "lat": 57.7089, "lon": 11.9746, "k": "point" } ] }
```

`k` is the kind of shape: a point's label goes beside it, a line's and a polygon's on it.
Empty below `labelminzoom` or outside the overlay's zoom range. `400 BAD_REQUEST`,
`404 OVERLAY_UNKNOWN`, `503 OVERLAY_NOT_READY`.

## 4. Datasource configurations

A configuration is a settings file on the server (`etc/datasources/`). Each running
datasource is created from one.

### 4.1 `GET /api/datasourceconfigs`

All valid configurations. The server reads the folder again on every call.

```json
{
  "datasourceconfigs": [
    {
      "id": 227688254,
      "name": "HLA3-RPR2",
      "file": "hla3-rpr2.datasource.settings",
      "standard": "IEEE1516_2025",
      "standardlabel": "HLA 4 (IEEE 1516-2025)",
      "hlafomrootdir": ".\\etc\\fom\\ieee1516-2025",
      "hlafoms": ["RPR_FOM_v2.0_Link16_1516-2010.xml", "NETN-BASE.xml", "NETN-ENTITY.xml"],
      "hlalsd": "default",
      "hlalsds": ["default", "crc2"],
      "hlafederation": "test1",
      "hlafederatetype": "SimwRift",
      "hlareconnect": true,
      "hlareconnectintervalsecs": 5
    }
  ]
}
```

- `id` and `name` are always present. The other fields reflect the settings file, and new
  ones may appear; clients should ignore fields they do not know.
- `hlafederation` is the default federation name, used when creating a datasource.
- `hlalsd` is the default LSD (the first entry of `datasource.hla.lsd`), and `hlalsds` every
  choice, the default first. Another can be given when creating a datasource (5.2).
- `hladynamicfom` is true for a configuration with `datasource.hla.foms = dynamic`: the
  datasource takes the FOM from the federation when it joins (`hlafoms` is then `["dynamic"]`).
- DIS configurations have `disinterface`, `disport`, `disexid`, `disentitytimeoutsecs`. A C-DIS
  configuration (`"standard": "CDIS"`, label `C-DIS (SISO-STD-023-2024)`) also has
  `"cdis": {"updatemode":"full","fullupdatemultiplier":2.4,"timeoutmultiplier":2.4,"heartbeats":{...}}`
  (the decoder uses the timeout multiplier and the heartbeats, in seconds).
- No configurations: `{"datasourceconfigs": []}`.

### 4.2 `GET /api/datasourceconfig/{configid}/autofederations`

The federations that the configuration's RTI currently knows about, for picking one when
creating a datasource. Note the singular `datasourceconfig` in this path.

```json
{ "federations": ["test1", "test2", "Exercise-Blue"] }
```

- `{"federations": []}` when none were found, when `configid` is unknown, or when it is not
  an integer.
- The scan contacts the RTI, so it can take a moment. 0.11.5: the probe (one per standard and
  LSD, shared by the configurations) connects on the first scan; after a failed connect it is
  not tried again for 3 s, and the answer is `{"federations": []}` meanwhile.
- `?lsd=crc2` asks the RTI with that LSD instead of the configuration's default (one of its
  choices or any other). The Web UI sends the LSD chosen in the Create dialog. `standard` is
  sent too and ignored.

## 5. Datasources

### 5.1 `GET /api/datasources`

```json
{
  "datasources": [
    { "id": "bca5e158-e9b8-46b1-939d-e941c54755d1", "name": "HLA3-RPR2 - test1 - 170610ZOCT26" }
  ]
}
```

No datasources running: `{"datasources": []}`. A datasource appears here once it has
joined.

### 5.2 `POST /api/datasources`

Creates a datasource from a configuration: connects to the RTI, joins the federation and
subscribes. **The call returns when the join has succeeded or failed.** Allow 30 seconds or
more.

Request:

```json
{ "configid": 227688254, "federation": "test1" }
```

| Field | Required | Meaning |
|---|---|---|
| `configid` | yes | Configuration id from `GET /api/datasourceconfigs`. A number or a numeric string |
| `federation` | no | Federation to join. Must not be empty when given. Leave it out for configurations without a federation (DIS) |
| `lsd` | no | HLA: the LSD (1516-2025: the RTI configuration name) to connect with, instead of the configuration's default. One of `hlalsds` or any other; `""` is the RTI's own default. At most 512 characters, no control characters |

Reply `201 Created`:

```json
{
  "success": true,
  "datasource": { "id": "bca5e158-e9b8-46b1-939d-e941c54755d1", "name": "HLA3-RPR2 - test1 - 170610ZOCT26",
                  "hlalsd": "default" }
}
```

HLA datasources report the LSD they connected with as `hlalsd`, here and in `GET /api/datasources`.

| Status | `error.code` | When |
|---|---|---|
| `400` | `BAD_REQUEST` | No body, the body is not a JSON object, `configid` is missing, `federation` is empty, or `lsd` is not a usable LSD |
| `400` | `INVALID_REQUEST` | `configid` is not an integer |
| `404` | `CONFIG_NOT_FOUND` | No configuration with that id |
| `500` | `INTERNAL_ERROR` | Connecting or joining failed. `error.message` is the RTI's message, e.g. `hla.rti1516_2025.exceptions.ConnectionFailed: Address 'doesnotexist:8989' is unknown/invalid.` |

### 5.3 `GET /api/datasources/{dsid}`

One running datasource, with its state and database statistics.

```json
{
  "datasource": {
    "id": "bca5e158-e9b8-46b1-939d-e941c54755d1",
    "name": "HLA3-RPR2 - test1 - 170610ZOCT26",
    "state": "JOINED",
    "statemessage": null,
    "stats": {
      "state": "RUNNING",
      "seq": 48211,
      "instances": 3456,
      "removedretained": 3,
      "interactionsbuffered": 10000,
      "queue": 0,
      "queuehighwater": 812,
      "processed": 1203456,
      "failed": 0,
      "decodeerrors": 0,
      "unknowninstance": 0,
      "rejected": 0,
      "emptyupdates": 0
    }
  }
}
```

| Field | Meaning |
|---|---|
| `state` | `JOINED` for a running datasource. State changes are also sent live as `datasource.state` events (8.4) |
| `statemessage` | Explanation that goes with the state, or `null` when all is well |
| `stats.state` | State of the datasource's database: `RUNNING` while it accepts data (else `STOPPING`, `STOPPED` or `FAILED`) |
| `stats.seq` | Current `seq` (section 1) |
| `stats.instances` | Active object instances |
| `stats.removedretained` | Removed objects that are still kept for 30 s (section 10) |
| `stats.interactionsbuffered` | Interactions in the history buffer (max 10 000) |
| `stats.queue`, `stats.queuehighwater` | Received updates waiting to be processed, now and at the most |
| `stats.processed`, `stats.failed` | Updates processed, and updates that failed |
| `stats.decodeerrors` | Values that could not be decoded against the FOM |
| `stats.unknowninstance` | Updates for instances that were never discovered |
| `stats.rejected`, `stats.emptyupdates` | Updates refused because the database was not running, and updates without any values |

Some datasources also report `created`, `federation`, `configid` and `config` (a snapshot of
the configuration, in the format of 4.1). Treat them as optional.

Unknown or malformed `dsid`: `404` with `DATASOURCE_UNKNOWN`.

### 5.4 `DELETE /api/datasources/{dsid}`

Resigns from the federation, disconnects from the RTI and removes the datasource. Its
objects and interaction history are discarded. Pages that show it receive
`datasource.removed` (8.4).

| Status | `error.code` | Meaning |
|---|---|---|
| `204 No Content` | — | Removed (no body) |
| `404` | `UNKNOWN_DATASOURCE` | No running datasource with that id |
| `409` | `RESIGN_FAILED` | The RTI refused or failed the resign. The datasource is still listed |

Note that this `404` uses `UNKNOWN_DATASOURCE`, while the `GET` endpoints use
`DATASOURCE_UNKNOWN`. Clients should treat both the same.

## 6. Classes, objects and interactions

All endpoints in this section are `GET` (or `HEAD`) under `/api/datasources/{dsid}`. Each
reply carries the current `seq`. An unknown `dsid` gives `404 DATASOURCE_UNKNOWN`; any
other method gives `405 METHOD_NOT_ALLOWED`.

### 6.1 `GET …/classes`

The object classes that currently have instances, as a flat list:

```json
{
  "seq": 48211,
  "total": 3456,
  "classes": [
    { "classnameq": "HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.Aircraft", "count": 12 },
    { "classnameq": "HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.GroundVehicle", "count": 3368 },
    { "classnameq": "HLAobjectRoot.EmbeddedSystem.RadioTransmitter", "count": 40 }
  ]
}
```

- `count` = active instances of **exactly** this class, not counting subclasses.
- To build a tree, split `classnameq` at the dots, add the missing intermediate classes, and
  sum the counts upward.
- `total` = all active instances.

### 6.2 `GET …/objects`

Object instances in the **list view** (7.1): the object header plus a few key attributes.

| Parameter | Default | Meaning |
|---|---|---|
| `class` | all | Qualified class names, comma separated |
| `subclasses` | `true` | Include instances of subclasses of each `class` |
| `q` | — | Case-insensitive text search in `label`, `instancename` and the list-view attribute texts |
| `related` | `false` | Also include active objects that **refer to** a matched object. Example: `class=…Aircraft&related=true` also returns the radios hosted on those aircraft |
| `ids` | — | Exactly these instance ids, comma separated. All other filters are then ignored. Recently removed objects are included, with `"state": "removed"` |
| `sort` | `label` | `label` (A–Z), `class` (class name, then label), `lastupdated` (most recent first), `discovered` (newest first) |
| `offset` | `0` | Rows to skip |
| `limit` | `200` | Rows to return, 1–500. Larger values are reduced to 500 |

Booleans accept `true`/`false`, `1`/`0` and `yes`/`no`.

```json
{
  "seq": 48211,
  "total": 3368,
  "offset": 0,
  "limit": 200,
  "objects": [ { "…": "list-view objects (7.1)" } ]
}
```

- `total` counts all matches, so a client can page with `offset` until it reaches `total`.
- Without `ids`, only active objects are returned.
- `400 BAD_REQUEST` for an unknown `sort` value, or a non-integer `offset` / `limit`.

### 6.3 `GET …/objects/{instanceid}`

One object with **all** received attributes, fully decoded, and its relations to other
objects.

| Parameter | Default | Meaning |
|---|---|---|
| `view` | `full` | `full` (7.2, with `related`) or `list` (7.1) |

```json
{ "seq": 48211, "object": { "…": "full view (7.2)" } }
```

- A removed object can still be read for 30 seconds. It then has `"state": "removed"` and
  `"removed"` with the time of removal.
- `404 OBJECT_UNKNOWN` when the id is unknown or the object is gone.

### 6.4 `GET …/interactions`

Recent interactions from the datasource's history buffer (the last 10 000), **newest first**.
Parameters are shallow nodes (7.4).

| Parameter | Default | Meaning |
|---|---|---|
| `limit` | `200` | 1–1000 |
| `before` | — | Only interactions with a `seq` lower than this. To page back, pass the `seq` of the last interaction of the previous page |
| `class` | all | Qualified interaction class names, comma separated (`HLAinteractionRoot.WeaponFire`) |
| `subclasses` | `true` | Include subclasses of each `class` |
| `object` | — | Only interactions that refer to this `instanceid`, by instance name or entity id. An unknown id gives an empty list |

```json
{
  "seq": 48231,
  "more": true,
  "interactions": [ { "…": "interactions (7.6)" } ]
}
```

`more` is `true` when older matching interactions exist.

### 6.5 `GET …/interactions/{interactionid}`

One interaction with **full** parameter nodes (7.4). `interactionid` is `i48230`, or the
bare number `48230`.

```json
{ "seq": 48231, "interaction": { "…": "interaction (7.6)" } }
```

`404 INTERACTION_UNKNOWN` once the interaction has left the history buffer.

### 6.6 `GET …/map`

The objects of an object-list filter that have a position, for the map view. Takes the filter of
6.2 (`class`, `subclasses`, `q`, `related`, `ids`), plus `bbox=west,south,east,north` (degrees;
`west > east` crosses 180°), `limit` (default 5000, at most 20000), and the layer parameters
`events`, `beams` and `lasers` (below).

```json
{ "seq": 78, "now": 1792668477741,
  "matched": 13, "shown": 11, "children": 2, "unpositioned": 0, "truncated": false,
  "objects": [ {
      "id": "o1", "label": "VIPER 11", "name": "1-3-1",
      "classnameq": "HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.Aircraft", "class": "Aircraft",
      "entityid": "1-3-1", "force": "friendly", "forcetext": "Friendly",
      "lat": 59.6495589, "lon": 17.9665224, "alt": 6000.0, "hdg": 94.8, "gs": 230.0,
      "vn": -19.2, "ve": 229.2, "vd": 0.0, "age": 0.4, "frozen": false,
      "children": [ { "id": "o12", "label": null, "name": "1-3-1/radio-1", "class": "RadioTransmitter",
                      "classnameq": "…", "entityid": null, "relation": "hosted", "force": null } ] } ] }
```

- **Position:** the RPR `Spatial`, dead reckoned to `now` (as `DRSpatial`, at most 30 s ahead).
  `vn`, `ve`, `vd` are the velocity in m/s north, east, down, so a client can move the symbol on
  between polls. Objects without a position are only counted (`unpositioned`).
- **Carried objects:** an object with a `HostObjectIdentifier` (radios, emitter systems), an
  `IsPartOf` (mounted or attached entities) or an `EmitterSystemIdentifier` (beams) is listed in
  `children` of its top-most positioned host (`relation`: `hosted`, `partof` or `beam`; `parent`
  when its own host is a carried object; `force` as for the objects, 0.9.22), not on its own.
- A host that is not in the filter is still listed, with `"context": true`, so a matching carried
  object can be reached.
- `force` is `friendly`, `opposing`, `neutral`, `other` (from `ForceIdentifier`, including the
  `Friendly_2` … variants), or null.

**Map layers** (optional parameters):

- `events=<seq>`: fire and detonation events for the flashes. Pass `0` on the first call and the
  answer's `eventseq` afterwards. The first call gets the events of the last 3 s, later ones those
  since `<seq>` (at most 300, none older than 10 s). Classes with a `WeaponFire`, `Fire`,
  `DirectedEnergyFire`, `MunitionDetonation`, `Detonation` or `Explosion` segment count.
  Place: `FiringLocation` / `DetonationLocation`, else the firing object (fire) or the target, then
  the firing object (detonation), dead reckoned (`placed`: `location`, `firing`, `target`). `bbox`
  applies. Events without a place are counted in `eventsunplaced`.
- `beams=true`: the radar and jammer beams (`EmitterBeam` subclasses) of the objects in `objects`,
  through `EmitterSystemIdentifier` → the emitter system → its `HostObjectIdentifier` / `IsPartOf`.
  `relaz` is `BeamAzimuthCenter` in degrees from the host's heading, `az` the true bearing now,
  `sweep` the azimuth sweep on either side; `el`, `elsweep` in degrees; `erp` in dBm; `freq` and
  `prf` in Hz. `beamshidden` counts beams whose host is not drawn.
- `lasers=true`: the laser designators that are lasing (`EmbeddedSystem.Designator` and
  subclasses; `DesignatorOutputPower` above 0 or not given; `lasersoff` counts the others).
  The spot (`lat`, `lon`, `alt`) is on the designated object (`DesignatedObjectIdentifier`), dead
  reckoned, when it has a position and `RelativeSpotLocation` is within 50 m (`placed`: `target`);
  else `DesignatorSpotLocation` (`placed`: `location`). `host` is the drawn object the line starts
  from (via `HostObjectIdentifier` / `IsPartOf`); `fromlat` / `fromlon` the host's own position,
  `range` the straight-line distance to the spot in metres; `power` in W, `wavelength` in µm.
  `lasershidden` counts designators with no spot or no host position. The spot's own dead
  reckoning is not applied.

```json
{ …,
  "eventseq": 152,
  "events": [ { "id": "i149", "kind": "detonation", "class": "MunitionDetonation",
                "classnameq": "HLAinteractionRoot.MunitionDetonation",
                "lat": 57.31, "lon": 18.55, "alt": 0.0, "placed": "location", "age": 0.4,
                "firing": "o8", "firinglabel": "BMP 3", "target": "o4", "targetlabel": "GOTLAND",
                "munition": "2.9.225.2.0.0.0", "result": "Detonation" } ],
  "eventsunplaced": 0,
  "beams": [ { "id": "o16", "host": "o4", "kind": "radar", "class": "RadarBeam",
               "label": "1-3-4/emitter-1/beam-2", "system": "o14", "systemlabel": "1-3-4/emitter-1",
               "emitter": "B597Z", "emitterfunction": "EarlyWarningSurveillance", "function": "Tracking",
               "relaz": -147.57, "az": 54.54, "sweep": 2.0, "el": 1.0, "elsweep": 2.0,
               "erp": 72.0, "freq": 9.4E9, "prf": 1000.0, "sweepsync": 0.0 } ],
  "beamshidden": 0,

                "host": "o12", "hostlabel": "REAPER 1", "fromlat": 57.4032222, "fromlon": 18.5507018,
```

### 7.1 Object, list view

```json
{
  "instanceid": "o1042",
  "instancename": "HLAobject_17_42",
  "label": "VIPER 11",
  "classname": "Aircraft",
  "classnameq": "HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.Aircraft",
  "view": "list",
  "state": "active",
  "discovered": "2026-10-21T11:40:02.114Z",
  "lastupdated": "2026-10-21T11:43:12.345Z",
  "rev": 48207,
  "updatecount": 5123,
  "producer": "VBS4-1",
  "attributes": [
    {
      "name": "EntityIdentifier", "datatype": "EntityIdentifierStruct",
      "lastupdated": "2026-10-21T11:40:02.120Z", "rawsize": 6, "valueRaw": "00CD0003002A",
      "value": { "kind": "RECORD", "text": "205-3-42" }
    },
    {
      "name": "ForceIdentifier", "datatype": "ForceIdentifierEnum8",
      "lastupdated": "2026-10-21T11:40:02.120Z", "rawsize": 1, "valueRaw": "01",
      "value": { "kind": "ENUM", "text": "Friendly", "value": 1, "enum": "Friendly" }
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `instanceid` | Rift's id for the object (section 1, Identifiers) |
| `instancename` | The HLA object instance name. RPR `RTIobjectId` references point to it |
| `label` | Display name: the RPR `Marking` text when the object has one, else `instancename` |
| `view` | `"list"` or `"full"` |
| `state` | `"active"` or `"removed"`. A removed object also has `"removed"` with the time |
| `discovered` | When Rift discovered the object |
| `lastupdated` | Time of the last attribute update (or of the discovery) |
| `rev` | `seq` of the object's last change (section 1, Sequence numbers) |
| `updatecount` | Attribute updates received for the object |
| `producer` | Name of the federate that registered the object, when known |
| `attributes` | **List view:** only the key attributes chosen for the class on the server, as shallow nodes. **Full view:** all received attributes, as full nodes |

### 7.2 Object, full view

Same as 7.1 with `"view": "full"` and these differences:

- `attributes` has **every attribute received** so far, with full value nodes (7.4).
  - The key attributes of the list view come first, then the rest in FOM order.
  - Attributes never received are not listed.
  - Computed attributes are inserted right after the attribute they are based on.
    RPR: **`DRSpatial`**, the `Spatial` dead-reckoned to the time of the reply.
- `related` lists the references from and to the object (7.5).

### 7.3 Attribute or parameter

| Field | Meaning |
|---|---|
| `name` | Attribute or parameter name from the FOM |
| `datatype` | FOM datatype name, or `null` when unknown |
| `lastupdated` | When this value was received (attributes only) |
| `rawsize` | Size of the encoded value in bytes |
| `valueRaw` | The encoded value as hexadecimal text. At most the first 256 bytes |
| `rawtruncated` | `true` when `valueRaw` was cut. `rawsize` still gives the full size |
| `value` | The decoded value: a value node (7.4) |

### 7.4 Value node

Decoded values are trees of value nodes:

```json
{
  "kind": "VARIANT",
  "text": "DRM_FPW 59.329312 18.068581 120.4 m hdg 274.1",
  "fields": [
    { "name": "DeadReckoningAlgorithm", "kind": "ENUM", "text": "DRM_FPW", "value": 2, "enum": "DRM_FPW" },
    { "name": "SpatialFPW", "kind": "RECORD", "text": "…", "type": "SpatialFPStruct",
      "fields": [
        { "name": "WorldLocation", "kind": "RECORD", "text": "59.329312 18.068581 120.4 m",
          "fields": [
            { "name": "X", "kind": "FLOAT", "value": 3108934.25, "text": "3108934.25", "units": "m" },
            { "name": "Y", "kind": "FLOAT", "value": 1015246.5,  "text": "1015246.5",  "units": "m" },
            { "name": "Z", "kind": "FLOAT", "value": 5464532.0,  "text": "5464532.0",  "units": "m" }
          ] },
        { "name": "IsFrozen", "kind": "BOOLEAN", "value": false, "text": "false" }
      ] }
  ],
  "derived": [
    { "name": "Latitude",  "kind": "FLOAT", "value": 59.329312, "text": "59.329312", "units": "deg" },
    { "name": "Longitude", "kind": "FLOAT", "value": 18.068581, "text": "18.068581", "units": "deg" },
    { "name": "Altitude",  "kind": "FLOAT", "value": 120.4,     "text": "120.4",     "units": "m" },
    { "name": "Heading",   "kind": "FLOAT", "value": 274.1,     "text": "274.1",     "units": "deg" }
  ]
}
```

| Key | Present | Meaning |
|---|---|---|
| `kind` | always | `INTEGER`, `FLOAT`, `BOOLEAN`, `ENUM`, `TEXT`, `BYTES`, `RECORD`, `ARRAY`, `VARIANT`, `EMPTY` or `ERROR` |
| `text` | always | One-line display text. Use this for showing a value; it is defined for every kind |
| `value` | scalars | `INTEGER` and `FLOAT`: a number (a string when it is too large, see section 1, Values). `BOOLEAN`: `true`/`false`. `ENUM`: the numeric value. `TEXT`: the string. `BYTES`: hex text |
| `enum` | `ENUM` | Enumerator name from the FOM, or `null` when the value is not defined there |
| `units` | optional | Units from the FOM, e.g. `"m/s"` |
| `type` | full, optional | Datatype name of a nested node |
| `fields` | full, `RECORD` and `VARIANT` | Named child nodes `{"name": …, …node}` in FOM order. For a `VARIANT`: the discriminant first, then the selected alternative |
| `items` | full, `ARRAY` | Element nodes. Arrays of characters or octets are `TEXT` or `BYTES` nodes instead |
| `count` | full, `ARRAY` | Number of elements, also when `items` was cut |
| `truncated` | optional | `true` when `items` or a long `TEXT`/`BYTES` value was cut |
| `derived` | full, optional | Values computed from the node, kept apart from the FOM fields. RPR examples: latitude, longitude, altitude, heading, pitch, roll and speeds for `Spatial`; for the Link 16 JTIDS header, fields such as the source track number |
| `ref` | optional | The node refers to other objects (7.5) |
| `error` | optional | Why decoding failed. The node may be partly decoded; `text` and the attribute's `valueRaw` are still there |
| `warnings` | full, optional | `["…"]`, notes from decoding |
| `entitytype` | optional | 0.11.1: an entity type in words, see below |

**Entity types in words (0.11.1).** A node of an entity type (a record with the fields
`EntityKind`, `Domain`, `CountryCode`, `Category`, `Subcategory`, `Specific` and `Extra`, such as RPR's
`EntityTypeStruct`, in HLA and DIS datasources alike) has `entitytype` with what SISO-REF-010
calls it, when the server has the file (installation guide, 2.10) and the type's kind is not 0:

```json
"entitytype": {
  "text": "CV9040A", "context": "Armored Fighting Vehicle",
  "country": "SWE", "countryname": "Sweden",
  "matched": "specific", "complete": true, "source": "SISO-REF-010-v37",
  "path": [ { "level": "kind", "value": 1, "name": "Platform" },
            { "level": "domain", "value": 1, "name": "Land" },
            { "level": "country", "value": 205, "name": "Sweden" },
            { "level": "category", "value": 2, "name": "Armored Fighting Vehicle" },
            { "level": "subcategory", "value": 1, "name": "Combat Vehicle 90 (CV90)" },
            { "level": "specific", "value": 5, "name": "CV9040A" } ]
}
```

| Key | Meaning |
|---|---|
| `text` | The most specific name the file has: the extra (with its specific), specific or subcategory; else the category; else the domain and kind, e.g. `"Land platform"` |
| `context` | The broader name that goes with it: the category, or the domain and kind; absent when there is none |
| `country` / `countryname` | The country's ISO 3166 alpha-3 code and name; absent for country 0 or a code the file does not have |
| `matched` | The deepest level named: `kind`, `domain`, `country`, `category`, `subcategory`, `specific` or `extra` |
| `complete` | `false` when a non-zero level is not in the file (then `text` is the nearest broader name) |
| `source` | The file's title |
| `path` | Full nodes only: every level the file names, `{level, value, name}` |

`GET …/objects?q=` also finds objects by these names and by the country.

**Shallow and full nodes.**
- **Shallow nodes** have only `kind`, `text`, `value`, `enum`, `units`, `ref`, `error`,
  `truncated` and `entitytype` (without its `path`). They are used in list views, interaction lists and interaction events.
- **Full nodes** have the whole tree. They are used in the full view, in object patches and
  in `GET …/interactions/{interactionid}`.

### 7.5 References and relations

The server knows which values are references to other objects, from its configuration
(for RPR: `RTIobjectId`, `RTIobjectIdArray`, and `EntityIdentifierStruct` where it is not the
object's own identifier). Such a node has a `ref`:

```json
"ref": {
  "kind": "objectname",
  "keys": ["HLAobject_17_42"],
  "targets": [ { "instanceid": "o1042", "label": "VIPER 11", "classname": "Aircraft" } ]
}
```

| Key | Meaning |
|---|---|
| `kind` | `objectname` (key = an HLA instance name) or `entityid` (key = an RPR entity id `site-application-entity`, e.g. `"205-3-42"`). Other kinds may be added |
| `keys` | The referenced keys: one for a single reference, several for an array |
| `targets` | Same length and order as `keys`. Each is the referenced object, or `null` while it is not (yet) known or after it was removed |

A `ref` can sit on any node, also deep inside a record. The full view (7.2) also has a
`related` block with both directions:

```json
"related": {
  "outgoing": [
    { "attribute": "HostObjectIdentifier", "path": "HostObjectIdentifier", "kind": "objectname",
      "key": "HLAobject_17_42", "target": { "…": "list view of the target, or null" } }
  ],
  "incoming": [
    { "attribute": "HostObjectIdentifier", "path": "HostObjectIdentifier", "kind": "objectname",
      "key": "HLAobject_17_42", "source": { "…": "list view of the referring object" } }
  ],
  "incomingtotal": 3
}
```

- `outgoing`: the references this object makes. `target` is `null` while the referenced
  object is not known.
- `incoming`: the objects that refer to this one, e.g. the radios hosted on an aircraft. At
  most 100 are listed; `incomingtotal` gives the real number.
- `path` locates the reference inside the attribute, e.g. `"Members[3].Unit"`. For a
  top-level value it equals `attribute`.
- An array reference gives one entry per key.

## 8. Live events (SSE)

Changes are pushed as [Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html)
on one HTTP connection.

### 8.1 Connecting

```
GET /api/events?topics=<topic>,<topic>,…
```

- The **topics** select what the connection receives (8.2). They are matched exactly, and
  are fixed for the lifetime of the connection. To change them, open a new connection, then
  close the old one.
- No topics: `400`.
- On connect, the server sends `: connected` and `retry: 3000` (reconnect after 3 s).
- After 15 seconds without events, the server sends a `: keepalive` comment.
- There is **no replay**: no event ids, and events missed while disconnected are lost. After
  any reconnect, read the current state again over REST (8.5).
- Each connection has a bounded queue on the server. A client that reads too slowly is
  **disconnected**, and should reconnect and reload.

In a browser:

```js
const ds = 'bca5e158-e9b8-46b1-939d-e941c54755d1';
const topics = ['ds:' + ds, 'ds:' + ds + ':classes', 'ds:' + ds + ':interactions', 'obj:' + ds + ':o1042'];
const es = new EventSource('/api/events?topics=' + topics.map(encodeURIComponent).join(','));

es.addEventListener('cards-changed', e => {
  for (const { id: topic, patch } of JSON.parse(e.data)) { /* apply patch to topic */ }
});
es.addEventListener('interaction', e => { const ix = JSON.parse(e.data); /* … */ });
es.addEventListener('interaction.stats', e => { const stats = JSON.parse(e.data); /* … */ });
es.addEventListener('datasource.state', e => { const { state, statemessage } = JSON.parse(e.data); });
es.addEventListener('datasource.removed', () => es.close());
```

### 8.2 Topics

`{dsid}` is the datasource id, `{iid}` an instance id.

| Topic | Delivers |
|---|---|
| `ds:{dsid}` | Events `datasource.state`, `datasource.removed` and `interaction.stats` |
| `ds:{dsid}:objects` | Patches: objects discovered, changed in their list view, or removed |
| `ds:{dsid}:classes` | Patches: instance counts per class |
| `ds:{dsid}:interactions` | Event `interaction`, one per interaction (rate-limited, 8.4) |
| `obj:{dsid}:{iid}` | Patches: every attribute update of that one object |
| `comms:{dsid}` | Events `comms.tick` and `comms.chat` (0.12.0, section 15) |

Subscribe `obj:` topics only for the objects you need, for example the ones on screen. The
Web UI uses at most about 100 per connection.

### 8.3 Patches: the `cards-changed` event

Topics marked "patches" are not sent one change at a time. The server merges the changes
per connection, topic and field, and sends them together at a fixed interval (typically
every 250 ms) as **one** event:

```
event: cards-changed
data: [{"id":"<topic>","patch":{…}},{"id":"<topic>","patch":{…}}]
```

- `id` is the topic, and `patch` holds the fields that changed since the previous batch.
- A field that changed several times in one interval carries only its **latest** value.
- A field set to `null` is meaningful (see below). A field that is absent did not change.

**`ds:{dsid}:objects`**: key = instance id.

```json
{ "o1042": { "…": "list view (7.1)" }, "o1043": null }
```

- A list view means the object was discovered, or one of its key attributes (or its label)
  changed.
- `null` means the object was removed.

**`ds:{dsid}:classes`**: key = qualified class name, value = the current instance count of
exactly that class.

```json
{ "HLAobjectRoot.BaseEntity.PhysicalEntity.Platform.Aircraft": 13 }
```

Counts are absolute; `0` means the class has no instances left.

**`obj:{dsid}:{iid}`**: key = attribute name, value = the attribute (7.3) with a **full**
node. Fields starting with `@` describe the object:

```json
{
  "Spatial":  { "name": "Spatial", "datatype": "SpatialVariantStruct", "…": "…" },
  "DRSpatial": { "name": "DRSpatial", "…": "…" },
  "@rev": 48207,
  "@lastupdated": "2026-10-21T11:43:12.345Z",
  "@updatecount": 5124
}
```

| Field | Meaning |
|---|---|
| `<attribute>` | The new value of an attribute that was updated |
| `@rev`, `@lastupdated`, `@updatecount` | As `rev`, `lastupdated`, `updatecount` in 7.1. Ignore a patch whose `@rev` is not higher than the `rev` you have |
| `@state` | `"removed"` when the object was removed |
| `@related` | Optional: a new `related` block (7.5) |

**Computed attributes:** about once per second, the server also sends computed attributes
(RPR `DRSpatial`) for subscribed objects. These patches have **no `@rev`**, because the
object did not change, only time passed. Apply them without the `@rev` check, and keep
the `rev` you have.

### 8.4 Events

| Event | Topic | Data |
|---|---|---|
| `interaction` | `ds:{dsid}:interactions` | One interaction (7.6) with shallow nodes |
| `interaction.stats` | `ds:{dsid}` | Once per second while interactions arrive: `{"window": 1.0, "counts": {"<classnameq>": n, …}, "dropped": n}` |
| `datasource.state` | `ds:{dsid}` | `{"state": "…", "statemessage": "…" or null}` when the state changes (e.g. `JOINING`, `JOINED`, `CONNECTION_LOST`) |
| `datasource.removed` | `ds:{dsid}` | `{}`: the datasource was removed (by `DELETE`, or after losing the RTI connection). No more events follow for it |
| `comms.tick` | `comms:{dsid}` | Once per second while a page listens: the last whole second's activity per channel (15.4) |
| `comms.chat` | `comms:{dsid}` | A chat or image message: `{"channel": "…", "line": {…}}` (15.2) |

**Rate limit for interactions.** At most **50** `interaction` events per second are sent per
datasource; the rest are dropped from the stream, though they still go into the history
buffer (6.4).
- `interaction.stats.counts` counts **all** received interactions per class, so rates stay
  exact.
- `dropped` tells how many were not sent in that window.
- `window` is the length of the window in seconds.

### 8.5 Keeping a consistent view

To combine snapshots (REST) and changes (SSE) without gaps:

1. **Open** the event stream first, and wait until it is open.
2. **Read** the snapshots you need (`classes`, `objects`, `interactions`).
3. **Queue** the patches and events that arrive while a snapshot is loading, and apply them
   afterwards:
   - Apply an object patch only if its `@rev` is higher than the object's `rev`, except
     for computed-attribute patches without `@rev` (8.3).
   - Class counts are absolute, so their order does not matter.
   - Interactions can be de-duplicated by `interactionid`.
4. **After any lost connection**, reconnect and repeat from step 1. There is no replay.
5. **When changing `obj:` topics**, open the new connection before closing the old one.
   Then re-read the objects that became live with `GET …/objects?ids=…`.

## 9. Errors

Errors have a real HTTP status and this body:

```json
{ "success": false, "error": { "code": "OBJECT_UNKNOWN", "message": "No object o99999" } }
```

`message` is meant for people and may include text from the RTI. Program against `code`
and the HTTP status.

| Status | Code | Meaning |
|---|---|---|
| `400` | `BAD_REQUEST` | Invalid parameter or body; `message` says which |
| `401` | `AUTH_REQUIRED` | API authentication is on and the call has no valid token or session (14) |
| `403` | `ORIGIN_REFUSED` | A change with the session cookie from another site's page (14) |
| `429` | `TOO_MANY_ATTEMPTS` | Too many wrong tokens from this address; try again after `Retry-After` seconds (14) |
| `400` | `INVALID_REQUEST` | `POST /api/datasources`: `configid` is not an integer |
| `404` | `NOT_FOUND` | No such API path |
| `404` | `CONFIG_NOT_FOUND` | Unknown configuration id |
| `404` | `DATASOURCE_UNKNOWN` | Unknown datasource id (`GET` endpoints) |
| `404` | `UNKNOWN_DATASOURCE` | Unknown datasource id (`DELETE`) |
| `404` | `OBJECT_UNKNOWN` | Unknown instance id, or the object is gone |
| `404` | `INTERACTION_UNKNOWN` | The interaction has left the history buffer |
| `405` | `METHOD_NOT_ALLOWED` | Method not supported on this path; `message` names the allowed ones |
| `409` | `RESIGN_FAILED` | `DELETE`: the resign failed |
| `500` | `INTERNAL_ERROR` | Joining failed (`POST`), or an unexpected server error |

The event stream (`/api/events`) answers its own errors (`400`, `405`) with a plain-text body.

## 12. Infra (0.9.20)

What the server has contact with: every DIS / C-DIS exercise its sockets hear and every HLA federation its federates have joined, from Rift's datasources and Junction's gateway endpoints (the Infra page). An **item** is one exercise or federation as one source sees it; its `key` (family, a dash, 12 hex digits) stays the same when the same datasource configuration or gateway starts again.

### 12.1 `GET /api/infra`

```json
{ "enabled": true, "now": 1792989909038, "mom": true, "pollseconds": 5.0,
  "dis6": [ ], "dis7": [ {item} ], "cdis": [ ], "hla3": [ {item} ], "hla4": [ ],
  "counts": {"dis6":0, "dis7":1, "cdis":0, "hla3":1, "hla4":0}, "listeners": 2, "federates": 1, "sources": 2 }
```

Every item has `key`, `family` (`dis6` `dis7` `cdis` `hla3` `hla4`), `protocol` (label), `name`, `source` `{kind: rift|junction, key, label, link}` (link: a page of this server), `rate` (messages per second over the last 5 s), `octetrate`, `history` (59 values: messages per second, oldest first), `last` (epoch ms), `status` (`active` within 5 s, `quiet`, `silent` after a minute; HLA without traffic yet: `joined`).

- DIS items add `exercise`, `versions`, `port`, `where` (the socket), `note` (what the owner does), `senders`, `entities`, `pdus`, `octets`, `first`.
- HLA items add `federation`, `connection` (the LSD, `RTI default`), `ownfederate`, `federates`, `joined`, `mom` (`waiting`, `ok`, `unavailable`), `momproblem` (only then), `rtiversion`. Their `rate` is what the source receives from the other federates.

### 12.2 `GET /api/infra/items?keys=…`

`keys`: up to 64, comma separated. Returns `{"now": …, "items": [ … ]}` in the order asked; an item not there now is `{"key": "…", "missing": true}`. Asking for an HLA item counts as watching it: its MOM is asked every `infra.hla.pollseconds` for the next 30 s.

A full **DIS** item adds `pdutypes` `[{type, name, pdus}]` (most first), `datagrams` and `malformed` (the whole socket), `listeningsince`, `senderslimited` (only when over 2000 senders) and `senderlist`:

```json
{ "address": "192.0.2.10", "port": 5000, "local": false,
  "siteapps": [ {"site": 7, "app": 42, "pdus": 1188} ], "entities": 2,
  "pdutypes": [ {"type": 1, "name": "Entity State", "pdus": 1188} ],
  "pdus": 1204, "rate": 15.0, "octetrate": 2160, "first": …, "last": …, "status": "active", "history": [ … ] }
```

A full **HLA** item adds `federationinfo` (from `HLAmanager.HLAfederation`: `rtiversion`, `mimdesignator`, `fommodules`, `timeimplementationname`, `autoprovide`, `lastsavename` …, as the RTI gives them), `timeimplementation`, `mommissing` (MOM attributes and reports this RTI lacks), `momexceptions`, `declarationsavailable`, `pollseconds` and `federatelist`:

```json
{ "name": "BlueSim", "frommom": true, "handle": "00000069", "self": false, "type": "Tester", "host": "sim-04",
  "rtiversion": "…", "state": "active", "timestate": "granted", "timeregulating": false, "timeconstrained": false,
  "logicaltime": "12.5", "lookahead": "0.1",
  "mom": { "HLAupdatesSent": 62, "HLAreflectionsReceived": 0, … },
  "momrates": { "updatessent": 11.0, "reflectionsreceived": 0.0, "interactionssent": 1.0, "interactionsreceived": 0.0 },
  "momupdated": …, "resigned": …,
  "observed": { "updates": 62, "interactions": 1, "updaterate": 12.4, "interactionrate": 0.2, "octetrate": 149, "last": …, "history": [ … ] },
  "declarations": { "requested": …, "received": …,
     "publications":  { "objects": [ {"class": "HLAobjectRoot.…Aircraft", "attributes": ["Marking", "Spatial"]} ], "objectclasses": 1,
                        "interactions": [ {"class": "HLAinteractionRoot.WeaponFire"} ] },
     "subscriptions": { "objects": [ {"class": "…", "active": true, "attributes": [ … ]} ], "objectclasses": 1,
                        "interactions": [ {"class": "HLAinteractionRoot.Detonation", "active": true} ] } } }
```

- `handle`: the federate handle as the RTI encodes it, in hex. `self`: the source's own federate. `momrates` come from successive MOM counter values (null until two have come). `observed` is what the source received from that federate (only when the RTI tells the producing federate).
- A federate seen only by its traffic (not in the MOM) has `frommom: false`, `name` and `observed`.
- `state`: `active`, `saving`, `restoring` (HLAfederateState 1, 3, 5). `logicaltime` / `lookahead` are read as HLAinteger64Time when the time implementation says integer, else HLAfloat64Time.

### 12.3 `GET /api/infra/items/{key}`

`{"item": {…}}`, the same full item; 404 `ITEM_UNKNOWN` when it is not there now.

### 12.4 `POST /api/infra/items/{key}/refresh`

HLA: asks the MOM for every federate's values now. 202 `{"success": true}`; 404 `ITEM_UNKNOWN`.

### 12.5 `POST /api/infra/items/{key}/declarations`

Body `{"federate": "<handle hex>"}`. Sends `HLArequestPublications` and `HLArequestSubscriptions` for that federate; the RTI's reports fill its `declarations` in the item (a moment later). 202 `{"success": true}`; 400 `BAD_REQUEST` (no or a malformed handle), 404 `ITEM_UNKNOWN`, 409 `MOM_REQUEST_FAILED` (no such federate, the RTI's MOM has no such requests, or the RTI refused).

## 14. Authentication (0.11.0)

Off unless the server has `api.auth.enabled=true` (installation guide, 2.9). Then every call under
`/api` needs one of:

- **A token** in the header, for programs (RFC 6750):
  `Authorization: Bearer swt_VHuYdfV1XddBP5F2VOzsBSGNGTKyOoKLX3FGXwwC_-g`. Tokens are made on the
  server with `run.sh --new-token=<name>`; there is one access level, so a token may do everything.
- **The session cookie** `simweaver_session`, for the Web UI: set by signing in (14.2), sent by the
  browser with every request under `/api`, the event stream and map tiles included. With the cookie, a
  call that changes something (not `GET` / `HEAD`) must carry this server's own `Origin`
  (`https://<host>:<port>`, or one of `api.auth.origins`), else `403 ORIGIN_REFUSED`; programs that
  send neither `Origin` nor `Sec-Fetch-Site` are not affected.

Without either, or with a token the server does not know (or that has expired), the answer is
`401 AUTH_REQUIRED` with `WWW-Authenticate: Bearer realm="SimWeaver"` (and `error="invalid_token"`
when a token was sent). After 10 wrong tokens within a minute from one address, calls with a token
from it, and sign-ins, get `429 TOO_MANY_ATTEMPTS` with `Retry-After: 60`; sessions already signed in
carry on. The web pages themselves (`/`, `*.html`, scripts) need no token.

`/api/auth` itself is always reachable:

### 14.1 `GET /api/auth/whoami`

```json
{ "auth": { "enabled": true, "name": "ops-wall", "via": "bearer" } }
{ "auth": { "enabled": true, "name": "ops-ui", "via": "session", "expires": "2026-10-30T02:18:36.319Z" } }
{ "auth": { "enabled": false } }
```

`name` is the token's name, `via` how it came (`bearer` or `session`), `expires` when the session
ends. `401 AUTH_REQUIRED` when authentication is on and the call has neither.

### 14.2 `POST /api/auth/session`

Body `{"token": "swt_…"}`: signs a browser in (the login page). `200` with the same body as whoami
and `Set-Cookie: simweaver_session=…; Path=/api; Max-Age=43200; HttpOnly; Secure; SameSite=Strict`
(`Max-Age` from `api.auth.sessionhours`). `400 BAD_REQUEST` (no `token`), `401 TOKEN_INVALID`,
`403 ORIGIN_REFUSED` (from another site's page), `409 AUTH_OFF` (authentication is off: nothing to
sign in to), `429 TOO_MANY_ATTEMPTS`.

A session ends after `api.auth.sessionhours`, when its token is revoked or expires, at a restart of
the server, or with 14.3.

### 14.3 `DELETE /api/auth/session`

Signs the browser out: `204` and the cookie cleared.

## 15. Comms (0.12.0)

The communication channels a datasource sees, for the Comms page (`comms.html?id=<dsid>`):

- **HLA Comms** (the HLA Comms FOM's channel, client, user and equipment objects and its message
  interactions): the channel objects (voice, radio, chat) and the lobby, with the senders (the HLA
  Comms clients) heard in them. Text and image messages make a transcript; PCM16 audio can be
  listened to (`datasource.comms.samplerate`, default 16000, and `datasource.comms.pcmbyteorder`,
  default `little`, in the datasource configuration), and Opus
  (0.12.1: passed through as it is and decoded by the listener; the Web UI uses the browser's
  WebCodecs).
- **RPR / DIS radio**: one channel per frequency of the `RadioTransmitter` objects, which are listed
  with their host objects. `EncodedAudioRadioSignal` audio is matched to its transmitter by
  `StreamTag` and played when it is 16-bit linear PCM (either byte order), 8-bit linear PCM,
  mu-law or Opus (passed through, 0.12.1); other encodings (CVSD, GSM, …) are shown as not playable. The other `RadioSignal`
  classes (raw binary, Link 16, database index, application specific) count as activity, matched by
  `HostRadioIndex`. DIS datasources come through the same way (DIS arrives as RPR).

Channel ids: `t-<uuid hex>` (HLA Comms), `t-lobby`, `f-<hertz>` (radio), `x-…` (signals whose transmitter
is not known).

### 15.1 `GET /api/datasources/{dsid}/comms`

- `rev` changes when channels, senders or names change; `t` is the epoch second of the last

### 15.2 `GET …/comms/chat?channel=`

The transcript of a channel, oldest first (`limit`, default 200, at most 500; the server keeps 500
per channel): `{"channel", "name", "total", "lines": [{"seq", "time", "sender", "senderid", "kind": "text" | "image", "text"}]}`.
`404 CHANNEL_UNKNOWN` for an unknown channel.

### 15.3 `GET /api/audio/stream?ds=&channels=`

The audio of up to 32 channels of one datasource (`ds` = datasource id, `channels` = channel ids,
comma separated) as one long chunked `application/octet-stream` response of frames, little endian:

| Octets | Field |
|---|---|
| 0 | version (1) |
| 1 | type: 0 keep-alive (every 2 s without audio, no payload), 1 audio |
| 2 | encoding of the payload: 1 = 16-bit linear PCM, little endian, mono; 2 = one Opus packet (RFC 6716) as received (0.12.1; the sample rate field is then 48000, the decoder's rate) |
| 3 | reserved |
| 4–5 | channel: its position in `channels=` (0 based) |
| 6–7 | reserved |
| 8–11 | source: the sender's `id` in the channel listing |
| 12–15 | sample rate (Hz) |
| 16–19 | sequence number of the frame in this stream |
| 20–23 | payload length (octets) |
| 24–31 | server receive time, ms since 1970 (float64) |
| 32… | payload |

- The server converts every other playable encoding to PCM16 LE at the source's sample rate; Opus
  goes as it is, one packet per frame (0.12.1). The receiver decodes Opus, resamples and mixes (the
  Web UI uses WebCodecs and Web Audio).
- A listener that falls behind loses the oldest frames (about 5 s are kept per stream).
- To listen to other channels, open a new stream and close the old one. At most 16 streams per
  datasource (`429 TOO_MANY_LISTENERS`); `400 BAD_REQUEST` for a missing or bad `channels` or `ds`,
  `404 DATASOURCE_UNKNOWN`.
- It is under `/api`, so it needs the same authentication as the rest (section 14); the browser's
  session cookie travels with `fetch()`.

```sh
curl -k -N "https://localhost:8843/api/audio/stream?ds=$DS&channels=f-251000000" > radio.bin
```

```json
{ "rev": 17, "t": 1793698263,
```

## 16. MCP (0.14.0)

`POST /api/mcp` is a **Model Context Protocol** server (MCP, [modelcontextprotocol.io](https://modelcontextprotocol.io)) for AI assistants: read-only tools over what the datasources see, the gateways, J2J and Infra. Off unless `mcp.enabled=true`; settings and who may call it: [install guide 2.11](simweaver-rift-install-and-config.md).

### 16.1 Transport

- Streamable HTTP, JSON replies only: one JSON-RPC 2.0 message per `POST`, one JSON reply (`Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`). Notifications and responses are answered `202` without a body. No SSE stream, no sessions: `GET` and `DELETE` are `405` (`Allow: POST`). Batches (a JSON array) are `400`.
- **Protocol revisions:** `2026-07-28` (stateless: each request carries `params._meta["io.modelcontextprotocol/protocolVersion"]`, client info and capabilities, and the headers `MCP-Protocol-Version`, `Mcp-Method` and, for `tools/call`, `Mcp-Name`, which must match the body: else `-32020` HeaderMismatch, HTTP 400; `server/discover` is answered), and `2025-11-25`, `2025-06-18`, `2025-03-26` with the `initialize` handshake (no session id is assigned). A version the server does not know: `-32022`, with `data.supported`. Clients of the official MCP SDKs negotiate this themselves.
- **Capabilities:** `tools` only (`listChanged: false`). `tools/list` carries `ttlMs` (300000) and `cacheScope: "private"` in 2026-07-28.
- **Access:** with API authentication, `Authorization: Bearer <token>` only (the session cookie gives `401`); without it, local clients only unless `mcp.allowremotewithoutauth`. A foreign `Origin`: `403`. More than `mcp.ratelimit.perminute` requests per token (or address): `429` with `Retry-After`. Bodies over 1 MB: `413`.

### 16.2 Tool results

Each tool returns its answer as `structuredContent` (a JSON object, described by the tool's `outputSchema`) and the same as compact JSON text in `content[0].text`. Every answer has `asof`, the UTC time it is valid for; positions are dead reckoned to it.

- Units: metres, m/s, degrees (true), seconds; `*_nm` and `*_kt` give nautical miles and knots. Times are ISO 8601 UTC.
- Values are compact: enumerators by name, entity types in words with their country and code (`"CV9040A (SWE) [1.1.205.2.1.5.0]"`), references as `"<name> (<label>, <id>)"`, records as objects, arrays as lists (at most 50 elements, then `"… n more"`).
- Errors the assistant can correct (an unknown object, an ambiguous name, a class that does not exist, a datasource not given when several run, arguments that do not fit the schema) are tool results with `isError: true` and a text saying what to do, often with the candidates. An answer larger than `mcp.maxresultkb` is such an error too ("narrow the filter or lower the limit"). An unknown tool name is the JSON-RPC error `-32602`.
- **Objects** are named by their id (`o12`), instance name, marking / label, or entity id (`1-2-3`, `1:2:3`); a unique part of a name or label is enough. **Datasources** by id, name, configuration or federation; may be left out when only one runs.

### 16.3 Tools

| Tool | Arguments | Answers |
|---|---|---|
| `server_overview` | | Server (version, uptime, CPU, heap), the datasources with their object counts, gateways by state and the running ones, J2J state and members, Infra counts |
| `health_check` | `scope`: `all`, `datasources`, `gateways`, `j2j` | Findings with `severity` (`error`, `warning`, `info`), `subject`, `text`, `since`: datasources not joined or lost in the last hour, gateways failed or degraded, endpoints not joined or without traffic while others flow, send errors (per DIS send address), registration failures, queue drops, conversion failures, router problems, Kafka producer / consumer failing, C-DIS errors, J2J members not reachable or with another member list; `ok`, `counts` |
